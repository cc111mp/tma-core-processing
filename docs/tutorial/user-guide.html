TMA QC
Getting started.

Organize original images, reconstruct AF cores and register reviewed H&E pairs. Follow the same workflow from a terminal or Python.

Start with your folders

tma-study/
├── raw/                       Original NAS-style AF folders
├── he/HE_SLIDE_01/A1.tif       Original H&E core image
├── pairing/sections.csv       Reviewed section assignments
├── manifests/                 manifest.json → paired.json
├── geometry/                  Tile positions + held-out landmarks
├── models/                    Frozen illumination fields
├── configs/                   AF + research registration settings
└── runs/run01/                acquisitions/ · pairs/ · reports/

This is a recommended dataset layout. The raw importer follows the hierarchy on pages 2–3; the manifest sets the locations of the other files.

What it does

Stitches raw AF tiles into TMA core images, applies illumination correction and reviews each stage. Optional registration aligns an explicitly assigned H&E core.

What you receive

Native TIFFs, coverage maps, source checksums and HTML reports that link each result to its original images.

Understand the manifest

Users supply a raw root. The importer lists the candidate tiles and records their identities and checksums in manifest.json.

FieldRole
dataset_idThe study/collection identifier.
cores[].slideThe assigned slide identifier. Automatically imported values use cleaned folder labels and hash suffixes.
core, acquisition, channelThe core position, acquisition record and AF channel assignment.
cores[].uidThe unique core-acquisition reference used by processing and H&E pairing.
groupA reference to an illumination-group/model assignment.
fovs[]Selected tile IDs, original paths and full source SHA256s.
positionsPath to native tile geometry when using the default supplied-geometry backend.
pairs[]Optional AF–H&E section-pair assignments.

Keep the original image identity

"metadata": {
  "source_slide_label": "SLIDE_01_AF",
  "source_lamp_label": "middle lamp 275",
  "source_folder": "acquisition01/SLIDE_01_AF/A1/middle lamp 275",
  "source_FOV_set_verified": false
}

This is an illustrative fragment, not a complete manifest. Use the generated JSON rather than recreating machine IDs by hand.

Name hash

The short suffix on an imported ID distinguishes source labels. IDs depend on relative acquisition and lamp paths.

File checksum

The full SHA256 binds the record to the image bytes. It is a separate value from the short ID suffix.

Folder labels need their acquisition meaning. The importer preserves the original spelling; it does not establish a laboratory barcode, physical section identity or an AF–H&E match from that spelling alone.

PhoMedics / TMA QC03 · Processing

Add tile positions and models

The default workflow uses supplied native tile positions and frozen CIDRE illumination fields. Folder discovery prepares the image list; these assets make reconstruction executable.

1. Add a position for each tile

Save under geometry/ and set the core’s positions path in the manifest. Match every FOV ID exactly once.

{
  "coordinate_space": "native_pixels",
  "axes": "XY",
  "origin": "upper_left",
  "positions": [
    {"id": "1", "x": 0, "y": 0},
    {"id": "2", "x": 1600, "y": 0}
  ]
}

The positions above are illustrative, not a calibration for your scanner. Current blending requires nonnegative integer native-pixel coordinates. Set geometry_reviewed only after review. Optional MIST estimation requires explicit grid/sequence information and a working Java/classpath setup.

Stage 4 checks and flags for review. Geometry QC records overlap measurements and highlights the largest measured shifts in preview crops. It leaves tile positions and FOV order unchanged. Unavailable overlap measurements remain unassessed.

2. Assign a compatible correction model

"groups": [{
  "id": "COPY_THE_GENERATED_GROUP_ID",
  "flatfield": "../models/group01/flatfield.tif",
  "darkfield": "../models/group01/darkfield.tif",
  "model_metadata": "../models/group01/model.json"
}]

This is a manifest fragment. Keep the generated group ID used by its cores and replace the asset paths with real reviewed files. Compatibility depends on the acquisition settings. Folder similarity alone is insufficient.

The flatfield and darkfield are frozen correction fields. The model receipt records their origin and expected checksums. To fit new fields, use the separate fit-cidre workflow with a compatible pool and the pinned Java runtime.

Scientific review remains separate. Successful field application does not establish absolute fluorescence preservation. See docs/METHODS.md and docs/VALIDATION.md.

PhoMedics / TMA QC04 · Quality review

Connect each process to QC

Processing produces an image or a coordinate record. Its QC reads those results and saves measurements, evidence and review status separately.

StageWhat to review
1 · indexHashes, single raw plane, stored pixel segments and expected profile. Verifies listed files; missing physical acquisitions need an expected inventory.
2 · tile_qcLocal detail, saturation and zeros in raw FOVs. Unavailable-window reasons and native sampling coverage accompany the measurements.
3 · geometryNative tile positions: supplied by default, optionally estimated with reviewed MIST inputs.
4 · geometry_qcSimilarity and residual shifts in expected overlaps. Advisory flags leave FOV order and positions unchanged.
5 · illuminationCorrected tiles from the frozen flatfield and darkfield.
6 · illumination_qcRaw/selected overlap agreement, assessed coverage, signal spans and model gains. See page 11.
7 · mosaicNative raw and selected mosaics built with the same geometry and blending.
8 · mosaic_qcLocalized seam tails, global/local brightness patterns and acquisition coverage. See page 12.
9 · tissueProvisional possible-tissue and unknown covered-area maps.

Read execution and quality together

Execution

Did the stage complete, fail or wait for a prerequisite? A diagnostic crash is a software execution error.

Quality

review means inspect available evidence. not_assessed means a measurement is unavailable; it is not a pass.

Keep the reconstruction available. Diagnostic failure does not suppress an otherwise valid stitched image. Essential missing inputs can block dependent processing. Scientific acceptance requires review.

Focus is advisory. Constant or weak-detail windows cannot establish blur. Window/interior coverage is geometric sampling, including unavailable windows; it is not a blurred-tissue percentage. Tile-grid previews average counts and use native-histogram display limits.

PhoMedics / TMA QC04 · Quality review

Review illumination correction

Does the same tissue agree better across overlapping tiles, and what happened to its signal range?

Raw tiles + geometryFrozen correction fieldsSame supported pixelsBefore/after evidence
EvidenceHow to interpret it
Assessed / candidate pairsHow many geometric overlaps supplied measurable comparison evidence. This fraction describes pairs, not tissue area.
Exclusion reasonsInsufficient raw support, unavailable raw correlation or correlation below the selection rule. Excluded pairs remain unknown.
Mismatch measurementsRelative mean difference and matched-pixel differences, including p95 and worst-pair crops. A mean can hide equal and opposite local errors.
Signal spans + gainsPer-FOV raw/selected percentiles and span ratios at identical sampled coordinates, plus model-gain percentiles.
Exact signal collapseNative extrema show that varying raw counts became constant. Inspect the source, model and selected image for the cause.

Start with the evidence coverage

A pair is eligible with at least 256 raw-supported samples and raw correlation ≥ 0.8. These are uncalibrated selection rules, not image-quality acceptance thresholds. The same raw-selected pairs and pixels are used after correction.

Then inspect agreement and signal together

Lower mismatch supports improved overlap agreement. Signal compression can also reduce absolute differences. Relative mismatch avoids a fixed one-count denominator floor; two zero means are unassessed. Span ratios and model gains remain review measurements without automatic cutoffs.

Agreement is one part of validation. It does not establish absolute fluorescence preservation, independent geometric accuracy or performance across excluded overlaps.

Open the core report’s illumination section, overlap crops and illumination-qc.json. Retain the raw reference and compatible model receipt.

TMA QC · Getting started11 / 19
PhoMedics / TMA QC04 · Quality review

Review the assembled mosaic

Check native seam evidence, repeating brightness patterns and acquired support. Read local tails alongside whole-core summaries.

1. Find localized seam changes

Known overlap midlines are measured across adjacent native strips, with nearby control cuts where possible. The report retains seam medians, p95 and maximum steps. Distinct-seam counts include measurable low-signal and mixed strata; stratum counts remain separate.

Worst-seam records identify the FOV pair, native cut and largest measured line. A localized brightness step can remain visible even when the median is zero. Isolated peaks may be noise or anatomy; inspect p95, controls and the images together.

2. Compare global and local tile-pitch patterns

The fit uses every supported native row or column bin. Four orthogonal strips per axis preserve regional evidence that can cancel in a global average. Both before/after fits use the same raw-defined pixel support.

Saved measurementMeaning
Harmonic amplitudesCount amplitudes at the first three fitted harmonics of tile pitch.
Explained fractionHow much detrended projection variation the fitted harmonics explain. It is not an artifact probability.
Support + regionNative sample counts, strip coordinates and unavailable reasons. Global and local fit counts are shown separately.

Accumulation uses bounded 512 × 512 source patches. Preview profiles alone are averaged; their reduction cannot alias the native fit. Missing native bins stay excluded, and display bins containing a gap remain unknown.

3. Inspect coverage and original tissue

Use the shared-window raw/selected comparison, native TIFFs and coverage.tif. Coverage marks acquired image support. It does not prove the entire intended core was captured.

Keep the result advisory. Anatomy can repeat at tile spacing. Patterns may cancel within one strip or occur at other periods. A low score cannot certify a clean core, and no artifact-area fraction is reported.

Choose a method

Start with the defaults. Select another supported method when your study needs it, and keep the same manifests, stage sequence and QC records.

python -m tma_qc methods
python -m tma_qc run --help
ChoiceAvailable methods
Geometryprovided (default) or mist. MIST needs Java and a reviewed tile grid.
Illuminationcidre (default) applies frozen fields; none retains original counts.
Registrationprovided (default), experimental sift_affine, or integrated sift, orb, geometry_sift, geometry_roma.
Core transformsimilarity (default) or affine. The latter also allows shear and unequal scaling.
Local refinementnone (default) or optional bspline_mi.

Change a method at the terminal

python -m tma_qc run \
  --manifest /data/tma-study/manifests/paired.json \
  --config /data/tma-study/configs/af.toml \
  --out /data/tma-study/runs/geometry-sift \
  --registration-method geometry_sift \
  --registration-transform similarity \
  --set tile_qc.stride=128 --resume

plan accepts the same method and parameter options. For comparisons, keep inputs and evaluation points fixed, choose a separate run directory, and change one method or setting at a time.

Asset assignments take precedence. Supplied tile positions are used before MIST; a supplied pair transform is used before fitting. RoMa needs its extra and cached weights; B-spline/MI needs its extra. Missing prerequisites block that path.

Tile detail QC, mosaic blending and tissue support currently each use one method with tunable parameters. Geometry QC flags evidence for review and never changes tile order.

    manifest="/data/tma-study/manifests/paired.json",
    output="/data/tma-study/runs/geometry-sift",
    config="/data/tma-study/configs/af.toml",
    registration_method="geometry_sift",
    parameters={"tile_qc": {"stride": 128}}, resume=True,
)

One precedence rule

Defaults → TOML → parameter overrides → explicit method selectors. CLI overrides use repeated --set SECTION.KEY=VALUE with typed TOML values; Python uses nested dictionaries. Unknown names and invalid values are errors.

Repeat your intended settings when resuming. run --resume uses that invocation’s arguments. Effective main settings are saved in run.json; pair receipts also save resolved core settings. Relevant changes rebuild affected stages.

docs/SETTINGS.md lists all defaults, units and backend applicability.
configs/methods.example.toml is an annotated starting point.
Core methods use registration.matching.max_dimension; main registration.max_dimension belongs to legacy sift_affine.
